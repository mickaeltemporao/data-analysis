# Guidelines for AI Agents (`AGENTS.md`)

This repository contains the source code, lecture materials, and documentation website for **Data Analysis** (Sciences Po Bordeaux). 

AI coding agents working on this codebase must adhere to the following principles, conventions, and quality standards.

---

## 1. Pedagogical Integrity & Human Oversight

- **Human-in-the-loop**: All changes generated by AI agents are subject to review, validation, and curation by the course instructor.
- **Audience**: The primary audience consists of social science students with diverse backgrounds in statistics and computer science. Explanations must be intuitive, pedagogical, and clearly articulated without unnecessary jargon or over-engineering.
- **Open Science & Reproducibility**: Materials should emphasize transparent, reproducible workflows from data import to publication-ready output.

---

## 2. Core Curriculum & Technology Stack

When generating or editing examples, code snippets, documentation, or assignments, adhere strictly to the designated course tools:

- **Data Management**: Use [`pandas`](https://pandas.pydata.org/) for data structures (Series, DataFrame), filtering, subsetting, recoding, and data cleaning.
- **Data Visualization**: Use [`Altair`](https://altair-viz.github.io/) for declarative statistical visualizations (univariate distributions, bivariate relationships, faceted charts).
- **Statistical Modeling**: Use [`statsmodels`](https://www.statsmodels.org/) (specifically the formula API: `import statsmodels.formula.api as sm`) for linear regressions (OLS) and hypothesis testing.
- **Scientific Writing & Reporting**: Use [**Typst**](https://typst.app/) for manuscripts, handouts, and reproducible academic deliverables.
- **Development Environment**: Visual Studio Code with Jupyter Notebooks (`.ipynb`) in an isolated project virtual environment (`.venv`).

---

## 3. Documentation & Site Standards

The documentation site is built using **Material for MkDocs**.

- **Strict Validation**: Always ensure the site builds cleanly with no broken internal links or warnings:
  ```bash
  uv run mkdocs build --strict
  ```
- **Formatting Conventions**:
  - Keep heading hierarchies clean and consistent.
  - Avoid decorative emoji clutter in content subheaders.
  - Use GitHub-style alerts (`> [!NOTE]`, `> [!TIP]`, etc.) or MkDocs admonitions (`!!! note`, `!!! tip`) where appropriate.
  - Ensure all external and internal links are valid and active.
